> 子需求ID：P0-03

> 状态：待开发  
> 依赖：P0-01 计划组基础管理

---

## 一、需求概述

### 1.1 功能简介

配置质检任务的抽样策略和数据过滤规则，通过多维度的清洗和抽样，精准筛选高价值数据，避免资源浪费。

### 1.2 业务价值

- 控制质检成本（Token消耗）
- 过滤无效数据，提升质检效率
- 支持灵活的抽样策略

---

## 二、功能详情

### 2.1 抽样配置

**配置字段：**

| 配置项 | 字段名 | 类型 | 必填 | 可选值 | 默认值 | 说明 |
|--------|--------|------|------|--------|--------|------|
| 抽样方式 | samplingMethod | 下拉选择 | ✅ | 随机抽样/最新优先/全量 | 随机抽样 | 定义数据选取逻辑 |
| 抽样数量 | maxCount | 数字输入 | ✅ | 1~10000 | 500 | 单位：条 |
| 抽样范围 | samplingScope | 下拉选择 | ✅ | 每个游戏抽取该数量/所有游戏共抽取该数量 | 每个游戏 | 定义抽样维度 |

**抽样方式详细说明：**

| 抽样方式 | 字段值 | 逻辑说明 | 适用场景 | 数据分布 |
|----------|--------|----------|----------|----------|
| 随机抽样 | random | 从符合条件的数据中随机选取 | 日常质检，保证样本分布均匀 | 均匀分布 |
| 最新优先 | latest | 按时间倒序选取最新数据 | 关注近期数据质量 | 时间集中 |
| 全量 | all | 对所有符合条件的数据质检 | 专项全量检查（注意资源消耗） | 全覆盖 |

**抽样范围详细说明：**

| 选项 | 字段值 | 逻辑 | 示例 |
|------|--------|------|------|
| 每个游戏抽取该数量 | perGame | 每个游戏独立抽样 | 配置500条，3个游戏则共抽取1500条 |
| 所有游戏共抽取该数量 | total | 所有游戏合计抽样，按各游戏数据量比例分配 | 配置500条，3个游戏共抽取500条 |

### 2.2 数据过滤规则

**过滤配置字段：**

| 配置项 | 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|--------|------|------|--------|------|
| 过滤纯Bot会话 | filter.excludePureBot | 开关 | ❌ | 开启 | 过滤仅Bot推送消息且用户未回复的会话 |
| 过滤用户未回复 | filter.excludeNoReply | 开关 | ❌ | 开启 | 过滤用户无任何回复的会话 |
| 黑名单关键词 | filter.blacklistKeywords | 标签输入 | ❌ | [] | 命中关键词的会话/单轮直接跳过 |
| 最小消息数 | filter.minMessages | 数字输入 | ❌ | 1 | 会话消息数低于此值则过滤 |
| 最大消息数 | filter.maxMessages | 数字输入 | ❌ | 不限 | 会话消息数高于此值则过滤 |

**角色交互过滤展示：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 过滤纯Bot会话 | 过滤仅Bot推送消息且用户未回复的会话 | 开关组件，开启为蓝色 | 🔵 已开启 |
| 过滤用户未回复 | 过滤用户无任何回复的会话 | 开关组件 | 🔵 已开启 |

**关键词黑名单展示：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 黑名单关键词 | 命中关键词的会话直接跳过 | 标签形式展示，支持添加/删除 | [测试] [忽略] [test] |
| 匹配规则 | 关键词匹配逻辑 | 文字说明 | 包含任一关键词即过滤 |

**消息数量过滤展示：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 最小消息数 | 会话消息数低于此值则过滤 | 数字输入框，最小值1 | 2 |
| 最大消息数 | 会话消息数高于此值则过滤 | 数字输入框，为空表示不限 | 100 |

### 2.3 过滤规则逻辑

- 多个过滤条件为 **OR** 关系，满足任一条件即被过滤
- 过滤在抽样之前执行，先过滤再抽样
- 被过滤的数据不消耗 Token，不计入质检数量

**执行顺序：**
```
原始数据 → 角色交互过滤 → 关键词过滤 → 消息数量过滤 → 抽样 → 质检执行
```

### 2.4 抽样结果统计（执行后展示）

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 原始数据量 | 清洗前的数据总量 | 数字 | 2000 |
| 清洗过滤量 | 被过滤的数据量 | 数字，灰色字体 | 500 |
| 符合条件量 | 清洗后的数据量 | 数字 | 1500 |
| 实际抽样量 | 最终抽取的数据量 | 数字，绿色字体 | 500 |

## 三、数据模型

### 3.1 抽样配置（SamplingConfig）

```typescript
interface SamplingConfig {
  samplingMethod: 'random' | 'latest' | 'all'  // 抽样方式
  maxCount: number                              // 抽样数量
  samplingScope: 'perGame' | 'total'           // 抽样范围
}
```

### 3.2 过滤配置（FilterConfig）

```typescript
interface FilterConfig {
  excludePureBot: boolean           // 过滤纯Bot会话
  excludeNoReply: boolean           // 过滤用户未回复
  blacklistKeywords: string[]       // 黑名单关键词
  minMessages: number               // 最小消息数
  maxMessages?: number              // 最大消息数（可选，不填表示不限）
}
```

### 3.3 抽样结果统计（SamplingStats）

```typescript
interface SamplingStats {
  originalCount: number      // 原始数据量
  filteredCount: number      // 过滤量
  qualifiedCount: number     // 符合条件量
  sampledCount: number       // 实际抽样量
  filterDetails: {           // 过滤详情
    pureBotFiltered: number
    noReplyFiltered: number
    keywordFiltered: number
    messageCountFiltered: number
  }
}
```

## 四、接口设计

### 4.1 更新抽样配置

```
PATCH /api/plan-groups/:id/sampling
```

**请求体**：SamplingConfig

### 4.2 更新过滤配置

```
PATCH /api/plan-groups/:id/filter
```

**请求体**：FilterConfig

### 4.3 预览抽样结果（不执行质检）

```
POST /api/plan-groups/:id/sampling-preview
```

**响应**：SamplingStats

## 六、验收标准

1. ✅ 抽样方式切换后逻辑正确（随机/最新/全量）
2. ✅ 抽样范围切换后计算正确（每游戏/总量）
3. ✅ 过滤开关可独立控制
4. ✅ 黑名单关键词支持添加、删除、多个标签展示
5. ✅ 消息数量范围校验正确（最小值≤最大值）
6. ✅ 过滤执行顺序正确（先过滤再抽样）
7. ✅ 执行后展示抽样统计结果

## 一、需求概述

### 1.1 功能简介

支持定时和手动两种触发方式执行质检任务，通过执行队列管理任务调度，实时展示执行进度。

### 1.2 业务价值

- 自动化执行质检任务
- 支持手动触发紧急质检
- 实时监控执行状态

---

## 二、功能详情

### 2.1 执行触发方式

| 触发方式 | 字段值 | 触发条件 | 说明 |
|----------|--------|----------|------|
| 定时触发 | scheduled | 到达配置的执行时间 | 系统根据计划组配置的执行周期和时间自动触发 |
| 手动触发 | manual | 用户点击"立即执行" | 无需等待定时，立即将任务加入执行队列 |

### 2.2 执行队列机制

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 队列位置 | 任务在执行队列中的位置 | 数字，实时更新 | 第3位 |
| 预计开始时间 | 根据队列位置估算的开始时间 | 时间格式：HH:mm | 约5分钟后 |
| 当前执行任务 | 正在执行的任务信息 | 计划组名-游戏渠道 | 甄选日常-穿越火线 |

**队列管理规则：**
- 同一计划组不可重复加入队列
- 若已在队列中，按钮置灰并显示"排队中"
- 手动触发的任务优先级与定时触发相同，按入队顺序执行

**交互说明：**
- 手动触发后显示Toast提示："任务已加入执行队列，当前排队第N位"
- 任务开始执行后，列表状态变为"执行中"，显示进度百分比

### 2.3 执行进度展示

**游戏渠道行进度展示：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 执行进度 | 当前完成百分比 | 进度条 + 百分比数字，蓝色填充 | ████░░░░ 65% |
| 完成/总数 | 已完成条数/总条数 | 格式：完成数/总数 | 325/500 |
| 预计剩余时间 | 根据当前速度估算 | 格式：约X分钟 | 约3分钟 |

### 2.4 执行状态流转

```
等待执行 → 排队中 → 执行中 → 已完成
                      ↓
                    异常
```

| 状态 | 状态值 | 颜色 | 触发条件 |
|------|--------|------|----------|
| 等待执行 | pending | ⚪ 灰色 | 未到执行时间，等待定时触发 |
| 排队中 | queued | 🟡 黄色 | 已加入队列，等待前序任务完成 |
| 执行中 | running | 🔵 蓝色 | 正在执行质检任务 |
| 已完成 | completed | 🟢 绿色 | 任务正常执行完毕 |
| 异常 | error | 🔴 红色 | 执行过程中发生错误 |

### 2.6 执行统计

任务执行完成后记录以下统计数据：

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 总任务数 | 本次需要质检的数据条数 | 数字 | 500 |
| 完成数 | 成功完成的条数 | 数字，绿色 | 480 |
| 失败数 | 质检失败的条数 | 数字，红色（>0时） | 20 |
| 缓存命中 | 复用已有结论的条数 | 数字 + 百分比 | 150 (30%) |
| 实际质检 | 调用LLM的条数 | 数字 | 330 |
| 节省Token | 预估节省Token数 | 数字 | 约45,000 |
| 总耗时 | 执行总时长 | X分X秒 | 12分30秒 |

## 三、数据模型

### 3.1 执行任务（ExecutionTask）

```typescript
interface ExecutionTask {
  id: string
  planGroupId: string
  gameChannelId: string
  triggerType: 'scheduled' | 'manual'
  status: 'pending' | 'queued' | 'running' | 'completed' | 'error'
  queuePosition?: number
  progress: number              // 0-100
  startTime?: string
  endTime?: string
  stats?: ExecutionStats
  errorInfo?: ErrorInfo
  createdAt: string
}
```

### 3.2 执行统计（ExecutionStats）

```typescript
interface ExecutionStats {
  total: number                 // 总任务数
  completed: number             // 完成数
  failed: number                // 失败数
  cacheHit: number              // 缓存命中数
  actualInspected: number       // 实际质检数
  tokenSaved?: number           // 节省Token数
  duration: number              // 耗时（秒）
}
```

### 3.3 执行记录（ExecutionRecord）

```typescript
interface ExecutionRecord {
  id: string
  planGroupId: string
  gameChannelId: string
  time: string
  triggerType: 'scheduled' | 'manual' | 'retryFailed' | 'retryAll'
  total: number
  completed: number
  failed: number
  cacheHit: number
  actualInspected: number
  tokenSaved?: number
  status: 'completed' | 'running' | 'error'
  duration?: number
  errorMessage?: string
  relatedExecutionId?: string   // 重跑时关联的原执行ID
}
```

## 四、接口设计

### 4.1 手动触发执行

```
POST /api/plan-groups/:id/execute
```

**请求体**：
```json
{
  "gameChannelIds": ["string"]  // 可选，不传则执行所有游戏渠道
}
```

**响应**：
```json
{
  "taskId": "string",
  "queuePosition": 3,
  "estimatedStartTime": "2026-01-20T10:05:00Z"
}
```

### 4.2 获取执行状态

```
GET /api/execution-tasks/:taskId
```

### 4.3 获取执行队列

```
GET /api/execution-queue
```

### 4.4 取消执行任务

```
DELETE /api/execution-tasks/:taskId
```

### 4.5 获取执行记录列表

```
GET /api/plan-groups/:id/executions
```

**查询参数**：
- `startDate`: 开始日期
- `endDate`: 结束日期
- `gameChannelId`: 游戏渠道ID
- `status`: 状态筛选

## 六、验收标准

1. ✅ 定时任务在配置时间正确触发
2. ✅ 手动触发后任务正确加入队列
3. ✅ 同一计划组不可重复加入队列
4. ✅ 执行进度实时更新（每10秒刷新）
5. ✅ 状态流转正确（pending→queued→running→completed/error）
6. ✅ 执行统计数据准确
7. ✅ 异常时正确记录错误信息

## 一、需求概述

### 1.1 功能简介

通过"计划组"批量管理多个游戏+渠道的质检任务，实现统一配置、统一监控。计划组是自动质检系统的核心管理单元。

### 1.2 业务价值

- 支持产品/运营人员自主配置质检计划
- 实现多游戏渠道的统一管理
- 提升配置效率，减少后台操作依赖

---

## 二、功能详情

### 2.1 计划组新建

**入口**：页面右上角"新建计划组"按钮

**配置弹窗分区**：

#### 一、基本信息

| 配置项 | 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|--------|------|------|--------|------|
| 计划组名称 | name | 文本输入 | ✅ | - | 唯一标识名称，最多50字 |
| 描述 | description | 多行文本 | ❌ | - | 补充说明，最多200字 |
| 关联质检规则 | ruleVersion | 下拉选择 | ✅ | 最新版本 | 选择已发布的质检规则版本 |
| 启用状态 | enabled | 开关 | ✅ | 开启 | 控制计划组是否参与定时执行 |

#### 二、执行计划配置

| 配置项 | 字段名 | 类型 | 必填 | 可选值 | 默认值 | 说明 |
|--------|--------|------|------|--------|--------|------|
| 执行周期 | cycle | 下拉选择 | ✅ | 每天/每周/自定义 | 每天 | 定义任务执行频率 |
| 执行时间 | executeTime | 时间选择器 | ✅ | 00:00~23:59 | 09:00 | 精确到分钟 |
| 周几执行 | weekDays | 多选复选框 | 条件必填 | 周一~周日 | 周一 | 仅"每周"模式下显示且必填 |
| 质检模式 | mode | 下拉选择 | ✅ | 会话标注/单轮标注 | 会话标注 | 定义质检颗粒度 |
| 质检数据范围 | dataRange | 下拉选择 | ✅ | T-1日/T-2日/自定义 | T-1日 | 指定质检的数据时间范围 |

**执行周期详细说明：**

| 周期类型 | 字段值 | 执行逻辑 | 配置示例 |
|----------|--------|----------|----------|
| 每天 | daily | 每天固定时间执行 | 每天 09:00 执行 |
| 每周 | weekly | 每周指定几天执行 | 每周一、三、五 09:00 执行 |
| 自定义 | custom | Cron表达式（高级） | `0 9 * * 1-5` 表示周一到周五9点执行 |

**质检模式详细说明：**

| 模式 | 字段值 | 质检粒度 | 适用场景 | Token消耗 |
|------|--------|----------|----------|-----------|
| 单轮标注 | single | 一问一答 | 知识准确性校验、敏感词检测 | 较低 |
| 会话标注 | session | 整场Session | 上下文逻辑一致性、服务态度评估 | 较高 |

### 2.2 计划组列表展示

**字段明细：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 计划组名称 | 计划组的唯一标识名称 | 支持点击展开/收起子列表 | 甄选日常质检计划 |
| 状态 | 计划组当前运行状态 | 彩色状态标签 | 🟢 正常 |
| 游戏渠道数 | 该计划组下关联的游戏渠道数量 | 数字 + "个游戏渠道" | 3个游戏渠道 |
| 执行周期 | 任务执行频率配置 | 周期+时间组合展示 | 每天 09:00 |
| 质检模式 | 会话标注或单轮标注 | 标签形式展示 | [会话标注] |
| 抽样配置 | 抽样数量和范围 | 数量 + 范围文案 | 500条/每游戏 |
| 最近执行 | 最近一次执行的时间 | MM-DD HH:mm | 01-16 09:00 |
| 启用开关 | 控制计划组是否启用 | Switch开关组件 | 🔵开启 |
| 操作 | 更多操作入口 | 下拉菜单按钮"⋯" | [⋯] |

**状态定义与颜色方案：**

| 状态 | 状态值 | 颜色 | 触发条件 |
|------|--------|------|----------|
| 正常 | normal | 🟢 绿色 | 计划组已启用，无异常，等待下次执行 |
| 执行中 | running | 🔵 蓝色 | 计划组下有任务正在执行 |
| 异常 | error | 🔴 红色 | 计划组下有游戏渠道处于异常状态 |
| 已停用 | stopped | ⚪ 灰色 | 计划组已手动停用 |

**展示规则：**
- 列表默认按创建时间倒序排列
- 异常状态的计划组置顶显示
- 点击计划组行可展开/收起游戏渠道子列表
- 无数据时显示空状态

### 2.3 计划组操作

| 操作 | 入口 | 说明 | 交互细节 |
|------|------|------|----------|
| 新建 | 页面右上角"新建计划组"按钮 | 弹窗表单创建 | 填写完成后点击"确定"保存 |
| 编辑 | 操作菜单"编辑配置" | 修改所有配置项 | 弹窗预填当前配置 |
| 删除 | 操作菜单"删除计划组" | 删除计划组及关联数据 | 二次确认弹窗 |
| 启用/停用 | Switch开关 | 实时切换启用状态 | 无需二次确认 |
| 导出结果 | 操作菜单"导出质检结果" | 导出质检结果 | 弹出导出配置弹窗 |
| 查看历史 | 操作菜单"查看历史记录" | 查看执行记录 | 弹出历史记录弹窗 |
| 立即执行 | 操作菜单"立即执行" | 手动触发执行 | 二次确认弹窗 |

## 三、数据模型

### 3.1 计划组（PlanGroup）

```typescript
interface PlanGroup {
  id: string                    // 计划组唯一标识
  name: string                  // 计划组名称
  description?: string          // 描述
  enabled: boolean              // 是否启用
  ruleVersion: string           // 关联的质检规则版本号
  cycle: 'daily' | 'weekly' | 'custom'  // 执行周期
  executeTime: string           // 执行时间
  weekDays?: number[]           // 周几执行
  cronExpression?: string       // 自定义Cron表达式
  mode: 'session' | 'single'    // 质检模式
  dataRange: string             // 质检数据范围
  gameChannels: GameChannelItem[]  // 游戏渠道列表
  createdAt: string
  updatedAt: string
  createdBy: string
}
```

## 四、接口设计

### 4.1 创建计划组

```
POST /api/plan-groups
```

**请求体**：PlanGroup（不含id、createdAt、updatedAt）

**响应**：创建成功的PlanGroup对象

### 4.2 获取计划组列表

```
GET /api/plan-groups
```

**查询参数**：
- `page`: 页码
- `pageSize`: 每页数量
- `status`: 状态筛选
- `keyword`: 关键词搜索

### 4.3 更新计划组

```
PUT /api/plan-groups/:id
```

### 4.4 删除计划组

```
DELETE /api/plan-groups/:id
```

### 4.5 切换启用状态

```
PATCH /api/plan-groups/:id/toggle
```

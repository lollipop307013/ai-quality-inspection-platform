## 一、需求概述

### 1.1 功能简介

为质检规则的大类和小类添加定义说明，为自动质检模型提供分类判断依据。模型在执行质检时，根据定义说明判断当前会话/消息应归属哪个分类。

### 1.2 业务价值

- **模型分类依据**：定义说明作为Prompt的一部分传入LLM，指导模型识别和分类质检问题
- **规则匹配参考**：告诉模型各分类的适用场景、触发条件和典型特征
- **结果一致性保障**：明确的定义说明可提升模型输出的一致性和准确性

**页面路径**：`质检中心 > 质检标准配置`

## 二、功能详情

### 2.1 定义说明展示

**列表展示字段：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 维度 | 质检规则的一级分组 | 文本，左对齐 | 对话、技术、业务 |
| 大类 | 质检规则的二级分类 | 名称 + 灰色小字备注（定义说明） | 人设一致性<br/><span style="color:gray">指Bot回复中的人设表现...</span> |
| 小类 | 质检规则的三级分类 | 名称 + 灰色小字备注（定义说明） | 按需使用<br/><span style="color:gray">根据用户需求灵活调整...</span> |
| 标准 | 质检判断标准 | 标签形式 | 称谓错误、语气不符 |
| 错误码配置项 | 关联的错误码标识 | 格式：#错误码 | #G0103 |
| 风险等级 | 该规则的风险等级 | 彩色标签 | 🔴高风险 / 🟡中风险 / 🟢低风险 |

**定义说明展示规则（单元格内备注形式）：**

| 场景 | 展示内容 | 样式 |
|------|----------|------|
| 已添加定义说明 | 名称下方显示定义说明文本 | 灰色小字（12px, #999），超长时截断显示 |
| 未添加定义说明 | 名称下方显示占位文本 | 灰色斜体：「+ 添加定义说明」 |
| hover状态 | 显示完整定义说明 | 原生title属性提示 |
| 点击定义说明 | 弹出编辑弹窗 | 可直接编辑定义说明 |

### 2.2 添加/编辑定义说明

**操作入口：**

| 入口位置 | 触发方式 | 说明 |
|----------|----------|------|
| 大类单元格 | 点击灰色备注区域 | 直接弹出编辑弹窗 |
| 小类单元格 | 点击灰色备注区域 | 直接弹出编辑弹窗 |
| 操作列 | 点击"..."菜单 > "编辑定义" | 编辑当前行的定义说明 |

**弹窗字段：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 分类名称 | 当前编辑的大类/小类名称 | 只读，文本展示 | 人设一致性 |
| 分类层级 | 当前分类所属层级 | 标签展示 | [大类] / [小类] |
| 定义说明 | 该分类的详细定义 | 多行文本输入框，最大500字 | 指Bot回复中的人设表现与预设人设不一致的情况... |
| 判断标准 | 质检时的判断依据（可选） | 多行文本输入框 | 1. 称谓与人设不符；2. 语气风格与人设不符... |
| 示例说明 | 典型案例说明（可选） | 多行文本输入框 | 正例：xxx；反例：xxx |

**交互说明：**
- 点击"添加定义说明"后弹出编辑弹窗
- 弹窗标题根据操作类型显示："添加定义说明" / "编辑定义说明"
- 保存后立即更新列表展示
- 支持清空定义说明（删除已有内容后保存）

### 2.3 删除大类

**操作入口：**

| 入口位置 | 触发方式 | 说明 |
|----------|----------|------|
| 大类行 | 点击"..."菜单 > "删除此大类" | 删除整个大类及其下所有小类 |

**确认弹窗字段：**

| 字段名称 | 说明 | 展示要求 |
|----------|------|----------|
| 警告标题 | 操作警告 | 红色文字，带警告图标 |
| 大类名称 | 待删除的大类 | 加粗文本 |
| 影响范围 | 删除后的影响说明 | 将同时删除该大类下的 N 个小类 |
| 操作按钮 | 确认/取消 | 危险操作使用红色按钮 |

**删除逻辑：**
- 删除大类时，同时删除该大类下的所有小类
- 已关联质检规则的大类不可删除，需先解除关联
- 删除操作不可恢复，需二次确认

### 2.4 导入导出功能

**导出功能：**

| 字段名称 | 说明 | 展示要求 |
|----------|------|----------|
| 导出格式 | CSV格式（可用Excel打开） | 支持UTF-8编码 |
| 导出列 | 含大类/小类定义说明 | 共10列 |

**导出CSV列结构：**

| 列序号 | 列名 | 说明 |
|--------|------|------|
| 1 | 维度 | 一级分组 |
| 2 | 大类 | 二级分类 |
| 3 | 大类定义说明 | 大类的定义说明文本 |
| 4 | 小类 | 三级分类 |
| 5 | 小类定义说明 | 小类的定义说明文本 |
| 6 | 标准 | 质检标准名称 |
| 7 | 错误码 | 错误码标识 |
| 8 | 描述 | 详细描述 |
| 9 | 严重程度 | 高/中/低 |
| 10 | 状态 | 启用/禁用 |

**导入功能：**

| 字段名称 | 说明 |
|----------|------|
| 支持格式 | CSV、JSON，自动识别 |
| 必要列 | 维度、大类、小类（缺少则报错） |
| 可选列 | 大类定义说明、小类定义说明（自动导入定义） |
| 导入结果 | alert弹窗提示导入数量 |

**导入逻辑：**
- CSV格式支持含逗号、引号的字段（标准CSV转义规则）
- 自动去重：相同大类/小类的定义说明只导入一次
- 兼容旧JSON格式（仅质检标准，无定义说明）

## 三、数据模型

### 3.1 分类定义（CategoryDefinition）

```typescript
interface CategoryDefinition {
  id: string
  gameId: string                // 游戏ID
  channel: string               // 渠道
  level: 'dimension' | 'category' | 'subcategory' | 'standard'  // 层级
  dimension: string             // 维度名称
  category?: string             // 大类名称
  subcategory?: string          // 小类名称
  standard?: string             // 标准名称
  definition: string            // 定义说明
  criteria?: string             // 判断标准
  examples?: string             // 示例说明
  createdAt: string
  updatedAt: string
  creator: string
}
```

### 3.2 质检标准（QualityStandard）

```typescript
interface QualityStandard {
  id: string
  dimension: string             // 维度
  category: string              // 大类
  subcategory: string           // 小类
  standard: string              // 标准
  code: string                  // 错误码
  description: string           // 描述
  severity: '高' | '中' | '低'  // 严重程度
  status: '启用' | '禁用'       // 状态
  createdAt: string
  updatedAt: string
  creator: string
}
```

## 四、接口设计

### 4.1 获取分类定义列表

```
GET /api/category-definitions
```

**查询参数**：
- `gameId`: 游戏ID
- `channel`: 渠道
- `level`: 层级

### 4.2 添加/更新分类定义

```
POST /api/category-definitions
PUT /api/category-definitions/:id
```

### 4.3 删除分类定义

```
DELETE /api/category-definitions/:id
```

### 4.4 导出质检标准

```
GET /api/quality-standards/export
```

**查询参数**：
- `format`: csv / json

### 4.5 导入质检标准

```
POST /api/quality-standards/import
```

**请求体**：FormData（文件上传）

> 子需求ID：P1-08

## 一、需求概述

### 1.1 功能简介

查看计划组下所有游戏渠道的历史执行记录，支持筛选和详情查看，便于追溯和问题分析。

### 1.2 业务价值

- 便于执行情况追溯
- 支持问题定位和分析
- 提供执行趋势参考

---

## 二、功能详情

### 2.1 入口方式

| 入口 | 说明 |
|------|------|
| 计划组操作菜单 | "查看历史记录" → 弹出历史记录弹窗 |
| 游戏渠道"最近执行"时间链接 | 点击 → 弹出该游戏渠道的执行详情 |
| 计划组展开后 | 游戏渠道列表下方显示"执行记录"Tab区域 |

### 2.2 历史记录列表字段

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 执行时间 | 任务开始执行时间 | 格式：YYYY-MM-DD HH:mm | 2026-01-15 09:00 |
| 游戏渠道 | 执行的游戏+渠道 | 格式：游戏名-渠道名 | 穿越火线-微信 |
| 总任务数 | 需质检的数据条数 | 数字 | 500 |
| 完成数 | 成功完成的条数 | 数字，绿色字体 | 480 |
| 失败数 | 质检失败的条数 | 数字，红色字体（>0时） | 20 |
| 缓存命中 | 复用已有结论的条数 | 数字 + 百分比 | 150 (30%) |
| 执行状态 | 任务执行状态 | 彩色状态标签 | 🟢已完成 / 🔵执行中 / 🔴异常 |
| 耗时 | 任务执行总耗时 | 格式：X分X秒 | 12分30秒 |
| 操作 | 操作按钮组 | 链接按钮 | [详情] [导出] [重跑] |

### 2.3 执行状态定义

| 状态 | 状态值 | 颜色 | 说明 |
|------|--------|------|------|
| 已完成 | completed | 🟢 绿色 | 任务正常执行完毕 |
| 执行中 | running | 🔵 蓝色 | 任务正在执行，显示进度百分比 |
| 异常 | error | 🔴 红色 | 任务执行过程中发生错误 |
| 已取消 | cancelled | ⚪ 灰色 | 任务被手动取消 |

### 2.4 筛选条件

| 筛选项 | 字段名 | 类型 | 默认值 | 说明 |
|--------|--------|------|--------|------|
| 时间范围 | dateRange | 日期范围选择器 | 最近7天 | 按执行时间筛选 |
| 游戏渠道 | gameChannels | 下拉多选 | 全部 | 筛选指定游戏渠道 |
| 执行状态 | status | 下拉选择 | 全部 | 全部/已完成/执行中/异常 |

**筛选逻辑：**
- 多个筛选条件为 **AND** 关系，取交集
- 筛选后列表实时刷新，显示符合条件的记录
- 无匹配数据时显示空状态："未找到符合条件的执行记录"

### 2.5 执行详情弹窗

点击"详情"后展示弹窗，包含以下区域：

**基本信息区：**

| 字段 | 说明 | 案例 |
|------|------|------|
| 计划组名称 | 所属计划组 | 甄选日常质检计划 |
| 游戏渠道 | 执行的游戏渠道 | 穿越火线-微信 |
| 执行时间 | 开始执行时间 | 2026-01-15 09:00:00 |
| 执行模式 | 定时触发/手动触发/重跑 | [定时触发] |

**执行统计区：**

| 字段 | 说明 | 案例 |
|------|------|------|
| 总任务数 | 本次质检数据条数 | 500 |
| 完成数 | 成功完成条数 | 480 |
| 失败数 | 失败条数 | 20 |
| 缓存命中 | 复用结论条数 | 150 |
| 实际质检 | 调用LLM条数 | 330 |
| 节省Token | 预估节省Token数 | 约45,000 |
| 总耗时 | 执行总时长 | 12分30秒 |

**质检结果分布区：**

| 结果 | 展示 | 案例 |
|------|------|------|
| 优秀 | 数量及占比，绿色柱状 | 200 (40%) |
| 合格 | 数量及占比，蓝色柱状 | 180 (36%) |
| 不合格 | 数量及占比，橙色柱状 | 80 (16%) |
| 风险 | 数量及占比，红色柱状 | 40 (8%) |

**异常信息区（若有异常）：**

| 字段 | 说明 | 案例 |
|------|------|------|
| 异常类型 | 异常分类 | 🔴 模型报错 |
| 异常详情 | 错误描述 | LLM服务响应超时 (Timeout) |

**操作按钮：**
- [导出本次结果]
- [重跑失败项]
- [关闭]

### 2.6 交互说明

- 列表默认按执行时间倒序排列
- 执行中的记录每10秒自动刷新进度
- 点击"重跑"按钮弹出确认框，选择"重跑失败项"或"全量重跑"

## 三、数据模型

### 3.1 执行记录（ExecutionRecord）

```typescript
interface ExecutionRecord {
  id: string
  planGroupId: string
  planGroupName: string
  gameChannelId: string
  gameName: string
  channelName: string
  time: string
  triggerType: 'scheduled' | 'manual' | 'retryFailed' | 'retryAll'
  total: number
  completed: number
  failed: number
  cacheHit: number
  actualInspected: number
  tokenSaved?: number
  status: 'completed' | 'running' | 'error' | 'cancelled'
  duration?: number             // 耗时（秒）
  progress?: number             // 进度（0-100）
  errorMessage?: string
  relatedExecutionId?: string   // 重跑关联的原执行ID
  resultDistribution?: {
    excellent: number
    qualified: number
    unqualified: number
    risk: number
  }
}
```

## 四、接口设计

### 4.1 获取执行记录列表

```
GET /api/plan-groups/:id/executions
```

**查询参数**：
- `startDate`: 开始日期
- `endDate`: 结束日期
- `gameChannelIds`: 游戏渠道ID（多个用逗号分隔）
- `status`: 状态
- `page`: 页码
- `pageSize`: 每页数量

### 4.2 获取执行详情

```
GET /api/executions/:executionId
```

### 4.3 获取执行统计

```
GET /api/executions/:executionId/stats
```

## 一、需求概述

### 1.1 功能简介

提供异常详情查看、自动重试机制、手动重跑操作等功能，确保质检任务的稳定运行和异常恢复。

### 1.2 业务价值

- 减少人工介入处理异常
- 提高任务执行成功率
- 保障数据完整性

## 二、功能详情

### 2.1 异常详情查看

**入口方式：**
- 状态为"异常"时，状态标签旁显示"查看"链接
- 点击告警消息中的详情链接
- 历史记录列表中点击异常记录的"详情"按钮

### 2.2 异常详情弹窗字段

**基本信息区：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 计划组名称 | 所属计划组 | 文本 | 甄选日常质检计划 |
| 游戏渠道 | 发生异常的游戏渠道 | 格式：游戏名-渠道名 | 穿越火线-微信 |
| 执行时间 | 任务开始执行时间 | YYYY-MM-DD HH:mm:ss | 2026-01-15 09:00:00 |
| 执行模式 | 定时触发/手动触发 | 标签 | [定时触发] |

**异常信息区：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 异常类型 | 异常分类 | 彩色标签 | 🔴 模型报错 |
| 发生时间 | 异常发生时间 | YYYY-MM-DD HH:mm:ss | 2026-01-15 09:15:30 |
| 摘要信息 | 简短的异常描述 | 文本，最多100字 | LLM服务响应超时 |
| 详细信息 | 完整的错误堆栈/日志 | 预格式化代码块，支持复制 | Error: Request timeout after 30000ms... |

**执行统计区：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 总任务数 | 本次质检数据条数 | 数字 | 500 |
| 完成数 | 成功完成条数 | 数字，绿色 | 450 |
| 失败数 | 失败条数 | 数字，红色 | 50 |
| 失败率 | 失败数/总数 | 百分比 | 10% |

**最近执行记录区：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 执行时间 | 执行开始时间 | MM-DD HH:mm | 01-15 09:00 |
| 执行状态 | 执行结果状态 | 彩色状态标签 | 🟢已完成 / 🔴异常 |
| 完成/失败 | 各状态数量 | 数字组合 | 480/20 |
| 耗时 | 执行总时长 | X分X秒 | 12分30秒 |

**操作按钮：**
- [重跑失败项]
- [全量重跑]
- [关闭]

### 2.3 异常类型标签定义

| 类型 | 字段值 | 标签文案 | 颜色 | 说明 |
|------|--------|----------|------|------|
| 缺数据 | dataMissing | 缺数据 | 🟠 橙色 | 数据源无可采集数据 |
| 模型报错 | modelError | 模型报错 | 🔴 红色 | LLM服务错误 |
| 资源不足 | resourceInsufficient | 资源不足 | 🟡 黄色 | Token不足或队列积压 |
| 进度异常 | progressAbnormal | 进度异常 | 🟣 紫色 | 执行时间过长 |
| 执行失败 | executionFailed | 执行失败 | 🔴 红色 | 任务整体失败 |

### 2.4 自动重试机制

**自动重试配置：**

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| 最大重试次数 | 自动重试的最大次数 | 3次 |
| 重试间隔 | 每次重试之间的等待时间 | 30秒 |
| 可重试错误类型 | 哪些错误类型会触发自动重试 | 网络超时、服务暂时不可用 |

**自动重试逻辑：**
- 仅针对可重试的错误类型
- 重试次数达到上限后标记为异常
- 每次重试记录日志
- 重试成功后状态恢复为正常

**可重试错误类型：**

| 错误类型 | 是否自动重试 | 说明 |
|----------|--------------|------|
| 网络超时 | ✅ 是 | 网络波动导致的临时性错误 |
| 服务暂时不可用 | ✅ 是 | 服务端临时过载 |
| Token超限 | ❌ 否 | 需要人工充值或调整配置 |
| 参数错误 | ❌ 否 | 配置问题，需要人工修复 |
| 数据异常 | ❌ 否 | 数据问题，需要人工排查 |

### 2.5 手动重跑操作

| 操作 | 字段值 | 说明 | 入口 | 交互细节 |
|------|--------|------|------|----------|
| 重跑失败项 | retryFailed | 仅重新执行失败的数据条目 | 操作菜单、异常详情弹窗 | 确认弹窗："确定重跑失败的50条数据？" |
| 全量重跑 | retryAll | 重新执行所有任务，忽略缓存 | 操作菜单、异常详情弹窗 | 确认弹窗："确定全量重跑？将忽略缓存重新质检所有数据" |

**重跑执行逻辑：**
- 重跑失败项：仅将失败的数据条目放入队列，不影响已成功数据
- 全量重跑：忽略缓存，强制重新质检所有数据并更新缓存
- 新增执行记录，标记执行模式（retryFailed / retryAll）
- 重跑任务进入队列后，状态变为"排队中"

### 2.6 重跑记录标识

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 执行模式 | 区分定时/手动/重跑 | 标签形式 | [定时] [手动] [重跑失败] [全量重跑] |
| 关联执行ID | 重跑任务关联的原执行记录ID | 可点击跳转 | 关联：exec_20260115_001 |

## 三、数据模型

### 3.1 异常信息（ErrorInfo）

```typescript
interface ErrorInfo {
  type: 'dataMissing' | 'modelError' | 'resourceInsufficient' | 'progressAbnormal' | 'executionFailed'
  code?: string                 // 错误码
  message: string               // 异常摘要
  detail?: string               // 详细信息/堆栈
  occurredAt: string            // 发生时间
  resolvedAt?: string           // 解决时间
  retryCount: number            // 已重试次数
  retryable: boolean            // 是否可重试
}
```

### 3.2 重试配置（RetryConfig）

```typescript
interface RetryConfig {
  maxRetries: number            // 最大重试次数
  retryInterval: number         // 重试间隔（秒）
  retryableErrors: string[]     // 可重试的错误类型
}
```

### 3.3 重跑任务（RetryTask）

```typescript
interface RetryTask {
  id: string
  originalExecutionId: string   // 原执行记录ID
  planGroupId: string
  gameChannelId: string
  retryType: 'failed' | 'all'   // 重跑类型
  failedDataIds?: string[]      // 失败数据ID列表（仅failed类型）
  status: 'queued' | 'running' | 'completed' | 'error'
  createdAt: string
  createdBy: string
}
```

## 四、接口设计

### 4.1 获取异常详情

```

```

### 4.2 重跑失败项

```
POST /api/executions/:executionId/retry-failed
```

### 4.3 全量重跑

```
POST /api/executions/:executionId/retry-all
```

### 4.4 获取重试配置

```
GET /api/settings/retry
```

### 4.5 更新重试配置

```
PUT /api/settings/retry
```

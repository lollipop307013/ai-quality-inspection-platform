# P2-11 告警通知机制

> 子需求ID：P2-11  
> 优先级：P2  
> 状态：待开发  
> 依赖：P2-10 监控指标配置  
> 被依赖：无

---

## 一、需求概述

### 1.1 功能简介

配置告警渠道和接收人，当监控指标触发阈值时，通过企微机器人或邮件发送告警通知。

### 1.2 业务价值

- 及时通知相关人员处理异常
- 减少问题发现到处理的时间
- 支持多渠道通知，确保消息触达

---

## 二、功能详情

### 2.1 告警配置

**计划组配置中的告警配置区域：**

| 配置项 | 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|--------|------|------|--------|------|
| 启用告警 | alert.enabled | 开关 | ❌ | 开启 | 是否启用异常告警通知 |

### 2.2 告警渠道配置

| 渠道 | 字段名 | 类型 | 说明 |
|------|--------|------|------|
| 企业微信机器人 | alert.channels.wechat.enabled | 开关 | 是否启用企微群机器人告警 |
| Webhook地址 | alert.channels.wechat.webhookUrl | 文本输入 | 企微机器人的Webhook URL |
| 邮件通知 | alert.channels.email.enabled | 开关 | 是否启用邮件告警 |

**告警渠道展示字段：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 企微机器人 | 是否启用企微群机器人告警 | 开关组件 | 🔵 已开启 |
| Webhook地址 | 企微机器人的Webhook URL | 文本输入框，支持校验URL格式 | https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx |
| 邮件通知 | 是否启用邮件告警 | 开关组件 | ⚪ 已关闭 |

### 2.3 告警接收人配置

| 配置项 | 字段名 | 类型 | 格式 | 示例 |
|--------|--------|------|------|------|
| 接收人列表 | alert.receivers | 标签输入 | rtx(姓名) | xiaohuwang(王小虎) |
| 邮箱 | - | 自动生成 | {rtx}@tencent.com | xiaohuwang@tencent.com |

**告警接收人展示字段：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 接收人列表 | 告警通知的接收人 | 标签形式，格式rtx(姓名) | [xiaohuwang(王小虎)] [zhangsan(张三)] |
| 邮箱 | 接收人的企业邮箱 | 自动生成，不可编辑 | xiaohuwang@tencent.com |

### 2.4 告警配置校验规则

- 启用告警后，至少选择一种告警渠道（企微或邮件）
- 启用企微告警后，Webhook地址为必填
- 接收人列表至少添加1人

### 2.5 告警触发条件

| 触发场景 | 告警级别 | 说明 |
|----------|----------|------|
| 任务整体失败 | 🔴 严重 | 任务执行过程中发生致命错误，无法继续 |
| 失败率超阈值 | 🟠 紧急 | 单次执行失败率超过监控配置的阈值 |
| 连续缺数据 | 🟡 警告 | 连续N次执行时数据量为0 |
| 资源不足 | 🟠 紧急 | Token余额不足或队列积压严重 |
| 进度异常 | 🟡 警告 | 执行时间超过预期 |

### 2.8 告警消息字段说明

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 告警标题 | 固定格式的标题 | 带emoji的警告标识 | ⚠️ [自动质检] 任务执行异常 |
| 计划组名称 | 发生异常的计划组 | 文本 | 甄选日常质检计划 |
| 游戏渠道 | 发生异常的游戏渠道 | 格式：游戏名 - 渠道名 | 地下城与勇士 - QQ |
| 异常类型 | 异常分类标签 | 带颜色emoji的标签 | 🔴 模型报错 |
| 失败原因 | 具体错误信息 | 文本描述 | LLM服务响应超时 (Timeout) |
| 失败数量 | 失败条数/总条数 | 数字 + 百分比 | 50/500 (10%) |
| 发生时间 | 异常发生时间 | YYYY-MM-DD HH:mm:ss | 2026-01-15 10:30:00 |
| @接收人 | 需要处理的负责人 | @rtx格式 | @王小虎 @张三 |
| 详情链接 | 跳转到异常详情页的链接 | 可点击URL | https://xxx.com/... |

### 2.9 企微 vs 邮件告警对比

| 对比项 | 企微机器人 | 邮件通知 |
|--------|------------|----------|
| 实时性 | ⭐⭐⭐ 即时推送 | ⭐⭐ 分钟级 |
| 信息量 | 简洁摘要 | 详细完整 |
| 交互性 | @提醒，群内讨论 | 邮件回复，可转发 |
| 适用场景 | 紧急告警，需快速响应 | 详细报告，需存档追溯 |
| 格式 | Markdown | HTML/纯文本 |

## 三、数据模型

### 3.1 告警配置（AlertConfig）

```typescript
interface AlertConfig {
  enabled: boolean
  channels: {
    wechat: {
      enabled: boolean
      webhookUrl: string
    }
    email: {
      enabled: boolean
    }
  }
  receivers: AlertReceiver[]
}

interface AlertReceiver {
  rtx: string
  name: string
  email?: string              // 自动生成
}
```

### 3.2 告警记录（AlertRecord）

```typescript
interface AlertRecord {
  id: string
  planGroupId: string
  gameChannelId?: string
  executionId?: string
  type: 'taskFailed' | 'errorRateExceeded' | 'dataMissing' | 'resourceInsufficient' | 'progressAbnormal'
  level: 'critical' | 'urgent' | 'warning'
  title: string
  content: string
  channels: ('wechat' | 'email')[]
  receivers: string[]
  status: 'pending' | 'sent' | 'failed'
  sentAt?: string
  errorMessage?: string
  createdAt: string
}
```

## 四、接口设计

### 4.1 更新告警配置

```
PATCH /api/plan-groups/:id/alert
```

**请求体**：AlertConfig

### 4.2 获取告警记录

```
GET /api/alerts
```

**查询参数**：
- `planGroupId`: 计划组ID
- `level`: 告警级别
- `status`: 发送状态
- `startDate`: 开始日期
- `endDate`: 结束日期

### 4.3 测试告警发送

```
POST /api/alerts/test
```

**请求体**：
```json
{
  "planGroupId": "string",
  "channel": "wechat" | "email"
}
```

### 4.4 重发告警

```
POST /api/alerts/:id/resend
```

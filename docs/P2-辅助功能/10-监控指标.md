---

## 一、需求概述

### 1.1 功能简介

对质检任务的运行状态进行全链路监控，配置异常监控指标和阈值，确保异常及时被发现。

### 1.2 业务价值

- 及时发现质检异常
- 减少人工巡检成本
- 保障数据完整性

---

## 二、功能详情

### 2.1 监控指标配置

**计划组配置中的监控配置区域：**

| 配置项 | 字段名 | 类型 | 必填 | 默认值 | 说明 |
|--------|--------|------|------|--------|------|
| 启用监控 | monitoring.enabled | 开关 | ❌ | 开启 | 是否启用异常监控 |

**监控指标详细配置：**

| 监控项 | 字段名 | 类型 | 阈值含义 | 默认阈值 | 说明 |
|--------|--------|------|----------|----------|------|
| 缺数据监控 | monitoring.metrics.dataMissing | 开关 + 数字 | 连续N次无数据 | 3次 | 数据源无可采集数据时告警 |
| 模型报错监控 | monitoring.metrics.modelError | 开关 + 数字 | 错误率 > N% | 10% | LLM服务报错、Token超限、API超时 |
| 资源不足监控 | monitoring.metrics.resourceInsufficient | 开关 + 数字 | 堆积 > N条 | 1000条 | 任务队列积压严重 |
| 进度异常监控 | monitoring.metrics.progressAbnormal | 开关 + 数字 | 预计超时N小时 | 2小时 | 执行时间异常过长 |

### 2.2 监控指标详细说明

| 监控项 | 字段名 | 监控类型 | 触发条件 | 默认阈值 | 告警级别 |
|--------|--------|----------|----------|----------|----------|
| 缺数据 | dataMissing | 任务级 | 连续N次执行时数据量为0 | 3次 | 🟡 警告 |
| 模型报错 | modelError | 条目级 | 单次执行中LLM调用失败率超过阈值 | 10% | 🔴 严重 |
| 资源不足 | resourceInsufficient | 系统级 | 待执行任务队列积压超过阈值 | 1000条 | 🟠 紧急 |
| 进度异常 | progressAbnormal | 任务级 | 执行时间超过预估时间N倍 | 2小时 | 🟡 警告 |

### 2.3 监控指标展示

**配置界面展示：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 缺数据监控 | 数据源无可采集数据 | 开关 + 阈值输入，格式"连续N次" | 🔵开启 · 连续3次 |
| 模型报错监控 | LLM服务报错、Token超限、API超时 | 开关 + 阈值输入，格式"错误率>N%" | 🔵开启 · 错误率>10% |
| 资源不足监控 | 任务队列积压严重 | 开关 + 阈值输入，格式"堆积>N条" | 🔵开启 · 堆积>1000条 |
| 进度异常监控 | 执行时间异常过长 | 开关 + 阈值输入，格式"超时N小时" | 🔵开启 · 超时2小时 |

### 2.4 监控数据面板

**监控面板展示字段：**

| 字段名称 | 说明 | 展示要求 | 案例 |
|----------|------|----------|------|
| 当前队列长度 | 待执行任务数量 | 数字，超阈值红色 | 156 |
| 今日执行总数 | 今日已执行的任务总数 | 数字 | 1,250 |
| 今日失败数 | 今日执行失败的任务数 | 数字，>0时红色 | 12 |
| 今日失败率 | 失败数/执行总数 | 百分比，超阈值红色 | 0.96% |
| 平均执行时长 | 今日任务平均执行时长 | 格式：X分X秒 | 8分30秒 |

### 2.5 告警级别定义

| 级别 | 颜色 | 说明 | 处理优先级 |
|------|------|------|------------|
| 🔴 严重 | 红色 | 任务完全无法执行，需立即处理 | 最高 |
| 🟠 紧急 | 橙色 | 影响任务执行效率，需尽快处理 | 高 |
| 🟡 警告 | 黄色 | 可能存在潜在问题，需关注 | 中 |
| 🔵 信息 | 蓝色 | 一般性通知 | 低 |

## 三、数据模型

### 3.1 监控配置（MonitoringConfig）

```typescript
interface MonitoringConfig {
  enabled: boolean              // 是否启用监控
  metrics: {
    dataMissing: {
      enabled: boolean
      threshold: number         // 连续N次
    }
    modelError: {
      enabled: boolean
      threshold: number         // 错误率百分比
    }
    resourceInsufficient: {
      enabled: boolean
      threshold: number         // 堆积条数
    }
    progressAbnormal: {
      enabled: boolean
      threshold: number         // 超时小时数
    }
  }
}
```

### 3.2 监控事件（MonitoringEvent）

```typescript
interface MonitoringEvent {
  id: string
  planGroupId: string
  gameChannelId?: string
  metricType: 'dataMissing' | 'modelError' | 'resourceInsufficient' | 'progressAbnormal'
  level: 'critical' | 'urgent' | 'warning' | 'info'
  value: number                 // 触发值
  threshold: number             // 阈值
  message: string               // 事件描述
  occurredAt: string
  resolvedAt?: string
  status: 'active' | 'resolved' | 'acknowledged'
}
```

### 3.3 监控统计（MonitoringStats）

```typescript
interface MonitoringStats {
  queueLength: number           // 当前队列长度
  todayTotal: number            // 今日执行总数
  todayFailed: number           // 今日失败数
  todayFailRate: number         // 今日失败率
  avgDuration: number           // 平均执行时长（秒）
  activeAlerts: number          // 活跃告警数
}
```

## 四、接口设计

### 4.1 更新监控配置

```
PATCH /api/plan-groups/:id/monitoring
```

**请求体**：MonitoringConfig

### 4.2 获取监控统计

```
GET /api/monitoring/stats
```

### 4.3 获取监控事件列表

```
GET /api/monitoring/events
```

**查询参数**：
- `planGroupId`: 计划组ID
- `level`: 告警级别
- `status`: 状态（active/resolved）
- `startDate`: 开始日期
- `endDate`: 结束日期

### 4.4 确认/解决监控事件

```
PATCH /api/monitoring/events/:id
```

**请求体**：
```json
{
  "status": "acknowledged" | "resolved"
}
```
